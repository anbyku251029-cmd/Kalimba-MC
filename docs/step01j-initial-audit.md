## 1. 기존 데이터 구조 및 분리 현황

### 1.1 기본 찬송가와 사용자 추가 찬송가 분리 여부
- **기본 제공 찬송가**: `src/data/hymns.ts`의 `DEFAULT_HYMN_SONGS` 배열에 총 20곡이 정적으로 정의되어 있습니다.
- **사용자 추가/수정 찬송가**: 브라우저 로컬스토리지 전용 키인 `custom_hymns_v1`에 저장되며, `src/components/SongSelectScreen.tsx`에서 런타임에 `DEFAULT_HYMN_SONGS`와 병합(`[...customHymns, ...DEFAULT_HYMN_SONGS]`)됩니다.
- **결론**: 기본 제공 찬송가 파일을 재구축하더라도 사용자의 로컬스토리지 데이터(`custom_hymns_v1`)는 전혀 침범되거나 초기화되지 않도록 완벽히 분리되어 있습니다.

### 1.2 곡의 고유 ID 체계
- **고급 음악**: `adv-1`부터 `adv-30`까지 30곡 고유 ID 보유.
- **찬송가**: `hymn-305`, `hymn-88` 등 찬송가 장수 번호를 접미사로 사용하는 고유 ID 보유.

### 1.3 숫자 악보 문법 (`noteParser.ts`)
- **숫자**: `1` (도/C4) ~ `7` (시/B4), `1'` (높은도/C5) ~ `7'` (높은시/B5), `1''` (2옥타브 높은도/C6) ~ `3''` (2옥타브 높은미/E6).
- **쉼표**: `0` (4분쉼표 1.0박), `0_` (8분쉼표 0.5박).
- **늘임표**: `-` (음표 길이 1박 연장), `--` (2박 연장), `---` (3박 연장).
- **8분음표**: `_` (0.5박으로 단축).
- **점음표 및 임의 박자**: `(1.5)` (점4분음표 1.5박 등 괄호 표기).
- **가사 연결**: `/` 기호 (예: `1/도`).

## 2. 기존 데이터의 음표 수 한계 분석

1. **기존 고급곡의 문제**:
   - `songsAdvanced.ts` 30곡 중 절반 이상의 곡이 25~35개 수준의 짧은 멜로디 1도막 형식으로만 작성되어 있어, '고급'이라는 명칭에 비해 곡이 너무 일찍 끝나고 완성도가 부족했습니다.
   - 목표: **30곡 전수 50음표 이상의 실제 연주 가능한 유효 음표(`playableNoteCount >= 50`)**를 확보하도록 전면 재구축.
2. **기존 찬송가의 문제**:
   - 찬송가 20곡 대부분이 1절 앞부분만 짧게 수록되어 있어, 예배와 묵상에 필요한 찬송가의 풍성한 은혜와 핵심 선율 반복(후렴 3~4회 반복)이 지원되지 않았습니다.
   - 목표: 찬송가 전곡을 실제 찬송가 악보의 절과 후렴 구조에 맞추어 충분한 음표 수로 재작성하고, 3~4회 반복 메타데이터와 재생 엔진을 지원하도록 개선.
